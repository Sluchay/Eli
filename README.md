# ЕЛИ — сайт ресторана

Сайт небольшого ресторана русской кухни: лёгкая первая страница, меню на одной
странице с якорной навигацией, доступ по QR-коду со стола и админка, из которой
владелец сам правит разделы, блюда, фото и цены.

Название читается дважды: **ели** — дерево, **ели** — глагол. Отсюда весь
визуальный язык: крафтовая бумага, глубокий хвойный зелёный, гравюрные ели,
шишки, латунные линейки. Палитра снята с реальной афиши ресторана.

## Как запустить сайт

**Самый простой способ.** Дважды щёлкните по файлу `start.cmd` в папке проекта.
Откроется чёрное окно, через пару секунд само откроется браузер с сайтом.
Чтобы остановить сайт — нажмите `Ctrl+C` в этом окне или просто закройте его.

Если сайт уже запущен, повторный запуск ничего не сломает: скрипт увидит это и
просто откроет браузер.

**Чтобы посмотреть сайт с телефона** (нужно для проверки QR-кода), запустите
`start.cmd lan` — в окне появится строка `Network` с адресом вида
`http://192.168.1.42:3000`, который и надо открыть на телефоне. Телефон должен
быть в той же сети Wi-Fi. Ссылка для QR-кода на стол собирается так:
`http://192.168.1.42:3000/menu?t=5`.

**Что делает скрипт.** Ищет Node.js в системе; если его нет, берёт встроенный в
среду DeepSeek Harness (в вашей системе обычный Node.js не установлен, поэтому
команда `pnpm dev` в терминале сама по себе не сработала бы). Затем проверяет,
установлены ли зависимости, и запускает сервер разработки.

**Если хочется всё делать руками** — установите Node.js 20 или новее с сайта
nodejs.org, выполните один раз `npm install -g pnpm`, и дальше в папке проекта
работают обычные команды:

```bash
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm dev
```

## Быстрый старт

Требуется Node.js 20 или новее и pnpm.

```bash
pnpm install          # установка зависимостей
cp .env.example .env  # Windows: copy .env.example .env
pnpm db:migrate       # создать базу и применить схему
pnpm db:seed          # наполнить демо-меню
pnpm dev              # запустить на http://localhost:3000
```

Открыть: главная — `/`, меню — `/menu`, меню для стола №5 — `/menu?t=5`,
бизнес-ланч — `/lunch`, афиша — `/events`, бронь — `/booking`,
политика — `/privacy`, админка — `/admin`.

Полезные команды:

```bash
pnpm typecheck        # проверка типов
pnpm build            # продакшн-сборка
pnpm db:studio        # просмотр базы в браузере
pnpm db:seed          # пересобрать демо-данные
```

Проверка, что всё живо (сервер должен быть уже запущен):

```bash
pnpm check:pages      # все публичные страницы отвечают и содержат нужный текст
pnpm check:admin      # защита админки, вход, кука сессии, доступ к разделам
pnpm check:styles     # стили и шрифты действительно собрались
```

`check:styles` существует не для красоты: страница может отдавать код 200 и
содержать все тексты, но остаться без стилей — тогда сайт выглядит как документ
из 1998 года, и ни один тест на текст этого не заметит.

## Админка

Адрес — `/admin`. Логин и пароль берутся из `.env` (`ADMIN_EMAIL`,
`ADMIN_INITIAL_PASSWORD`), по умолчанию `admin@eli.local` / `eli-admin-2024` —
**смените после первого входа**.

| Раздел | Что делает |
|---|---|
| Сводка | Сколько блюд, что в стоп-листе, сколько позиций ланча и афиши |
| Меню | Разделы и блюда: цена в рублях, метки, состав, аллергены, КБЖУ, фото, порядок |
| Стоп-лист | Один тап — «нет в наличии». Сделан под телефон, для работы во время смены |
| Бизнес-ланч | Надпись про часы подачи и публикации «картинка + текст» |
| Афиша | События с датой и анонсы без даты — просто фото и подпись |

В карточке блюда справа всё время видно, как её увидит гость: предпросмотр
обновляется по мере ввода. Изменения появляются на сайте сразу, перезапускать
ничего не нужно.

Фотографии сжимаются автоматически при загрузке: снимок с телефона на 4–6 МБ
превращается в WebP на 100–200 КБ, готовить его заранее не надо. Файлы лежат в
`data/uploads`, а не в `public`, поэтому переживают пересборку и не попадают в git.

Подробная инструкция простым языком, которую можно отдать владельцу ресторана, —
в `ADMIN-GUIDE.md`.

**Осторожно с `pnpm db:seed`:** он удаляет меню, ланчи и афишу и создаёт их заново
из демо-данных. Всё, что вы успели наредактировать через админку, будет потеряно.

## Как посмотреть сайт с телефона (нужно для проверки QR)

1. Узнайте адрес компьютера в локальной сети: `ipconfig` → строка «IPv4-адрес»
   (например `192.168.1.42`).
2. Запустите dev-сервер с доступом из сети:

   ```bash
   pnpm dev:lan
   ```

3. Откройте на телефоне `http://192.168.1.42:3000` — телефон должен быть в той же
   сети Wi-Fi.
4. Ссылку для QR-кода на стол собирайте так:
   `http://192.168.1.42:3000/menu?t=5`

Если страница не открывается — проверьте, что брандмауэр Windows не блокирует
Node.js в частных сетях.

## Принятые решения — и почему

**Меню — одна страница, а не страницы разделов.** Разделы это данные, а не
маршруты: если каждый раздел станет отдельным URL, то добавление раздела
потребует правок кода, а гость по QR попадёт не в полное меню. Текстовая часть
меню приходит в первом HTML-ответе, поэтому меню читается даже до загрузки
фотографий; картинки грузятся лениво.

**Цены хранятся в копейках, целым числом.** `690 ₽` в базе — это `69000`.
Дробные числа в деньгах рано или поздно дают ошибку в чеке. Форматирование —
в `lib/format.ts`.

**SQLite, а не PostgreSQL.** Для одного ресторана этого достаточно, база — один
файл, который легко бэкапить, и за неё не надо платить. Переезд на PostgreSQL —
смена `provider` в `prisma/schema.prisma` и строки `DATABASE_URL`.

**Списки хранятся как JSON-строки.** SQLite в Prisma не поддерживает ни `enum`,
ни `String[]`, поэтому метки, аллергены и соцсети лежат как JSON. Это осознанный
компромисс ради переносимости: схема таблиц при переезде на PostgreSQL не
меняется.

**Пароли — scrypt из `node:crypto`.** Никаких bcrypt и argon2: scrypt встроен в
Node, стоек и рекомендован OWASP. Меньше зависимостей — меньше поводов что-то
сломать при обновлении.

**Блюдо без фото выглядит намеренно.** Слева в карточке всегда квадрат одного
размера: либо фотография, либо гравюрная иконка раздела на крафтовом фоне. Из-за
этого соседство «с фото / без фото» не читается как недоделка. Пустые поля не
рендерятся вовсе — никаких «Вес: —».

**Карта подключается кнопкой, а не iframe.** Встроенная карта тянет сотни
килобайт сторонних скриптов, тормозит первый экран и раскрывает поведение гостя
третьей стороне. Кнопка «Построить маршрут» решает ту же задачу за один тап.

**В `.npmrc` включён плоский `node_modules`.** Так проект ставится и на Windows,
где создание симлинков запрещено системной политикой. На Linux и в Docker это
работает так же.

## Работа с базой

```bash
pnpm db:migrate                          # применить схему (создаёт миграцию)
pnpm db:seed                             # демо-данные
pnpm db:studio                           # веб-интерфейс к базе
```

Полный сброс базы:

```bash
rm -rf prisma/migrations data/eli.db     # Windows: удалить вручную
pnpm db:migrate
pnpm db:seed
```

Первый администратор создаётся сидом из переменных `ADMIN_EMAIL` и
`ADMIN_INITIAL_PASSWORD` (см. `.env.example`). Пароль по умолчанию обязательно
сменить — вход в админку появится на этапе 4.

## Переменные окружения

Все ключи с комментариями — в `.env.example`. Обязателен только `DATABASE_URL`.
Если `TELEGRAM_BOT_TOKEN` не заполнен, интеграция просто выключается: сайт
работает как обычно.

## Данные, которые нужно заменить

Демо-меню — это **стандартная схема** для локального ресторана: закуски, салаты,
супы, пицца, паста, горячее, гарниры, десерты, напитки, бар. Всё это заменяется
реальным меню через админку, править код для этого не нужно.

Список всех заглушек, которые надо заменить (адрес, телефон, часы, тексты,
юридические данные), — в файле `CONTENT-TODO.md`.

## Текущие ограничения этапа 3

- Админки ещё нет: меню правится в `prisma/seed.ts` и через `pnpm db:seed`.
- Форма брони не сделана — бронь идёт по телефону, и это указано на странице.
- Фотографий нет ни у одного блюда: работают гравюрные иконки разделов.
  Как только появятся фото, они подставятся в тот же квадрат карточки.
- QR-коды пока ведут на `/menu?t=<номер>`; генератор QR и печать появятся на
  этапе 6 вместе с динамическими ссылками `/m/<token>`.
- ESLint сознательно отложен до этапа 8, чтобы не тормозить первый показ.
